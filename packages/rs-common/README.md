# polycentric-common

Rust shared by everything that speaks the Polycentric protocol: the client
SDK ([rs-core](../rs-core/README.md)), the server, and the other services
(`services/*`, `tools/identity`). It holds the protocol's types and rules,
not any client or server behaviour.

## Contents

| Module | |
|---|---|
| `models::protos_v2` | the v2 protobuf types, generated by `build.rs` with prost/tonic from `protos/polycentric/v2/*.proto` (gRPC clients and servers too) |
| `models::protos` | the v1 types (used by `services/grayjay-migrator` and a few legacy models) and `rs-core-ffi.proto` |
| `models::*` | validation for each message (`validate.rs` and a module per type), collection ids (`collections`), identity derivation and recovery payloads (`identity`), moderation labels, content digests |
| `models::traits` | `Serializable` (decode-and-verify for signed types), id helpers |
| `signing` | ed25519 signing and verification |
| `jwt` | minting and verifying the bearer JWTs clients authenticate to servers with |
| `merkle` | the RFC 6962 Merkle trees behind `Event.previous_root` and event proofs |
| `alias` | `user@domain` aliases: parsing, normalizing, the `/.well-known/polycentric.json` lookup |
| `mentions` | mentions in post text (mirrors the app's `parseTextLinks`) |
| `platform` | error codes shared by the services |

Client hosts don't use these types directly: rs-core generates its own
UniFFI records from the same protos (see its README). The prost types here are
what rs-core uses internally and what goes on the wire.

## Features

- `transport`: tonic's transport, for native gRPC clients and servers.
  Services enable it; rs-core enables it only on native targets.
- `uniffi`: exports the validation error enums (`PostValidationError`,
  `ContentValidationError`, …) through UniFFI, for rs-core's
  `validate_content`. The crate also builds as a `cdylib` for that.

## Development

```sh
cargo test -p polycentric-common
cargo clippy -p polycentric-common
```

`build.rs` needs `protoc`. The protos live in the repository's top-level
`protos/` directory.
