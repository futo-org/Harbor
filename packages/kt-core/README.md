# polycentric-kt-core

Kotlin/Android SDK for Harbor. It mirrors `packages/js-core`: a
thin platform shell around the shared Rust protocol engine
(`packages/rs-core`), accessed through UniFFI-generated Kotlin bindings.
Ported code diverges from js-core on purpose in a few places, all
documented inline.

## Architecture

An app using this library runs on four layers, from top to bottom:

1. **The app** (e.g. [Grayjay](https://gitlab.futo.org/videostreaming/grayjay)) constructs a
   `PolycentricClient`, supplying storage and file-store drivers, and calls the client's functions.
2. **polycentric-core** is this library. It owns persistent storage and control flow, such as sync
   and initialization.
3. **The FFI** is generated by `uniffi-bindgen` from `rs-core`.
4. **rs-core** is the protocol engine shared with `js-core`. It owns sequences, Merkle anchors,
   vector clocks, validation, the query engine, gRPC transport with TLS, and image processing.

Protobuf messages are generated by [Wire](https://github.com/square/wire) from
`protos/polycentric/v2/*.proto`.

## Using this library

Published to the project's Forgejo Maven registry at `code.futo.org` on release tags as
`org.futo:polycentric-core`. Add the registry to your repositories:

```kotlin
maven {
    url = uri("https://code.futo.org/api/packages/harbor/maven")
}
```

What your app needs:

- `compileSdk` >= 35
- `minSdk` >= 24
- Kotlin >= 2.2
- JDK (for building, not runtime) >= 17

The AAR declares no minimum Gradle or AGP version, so those stay your choice.

Library classes are Java 17 bytecode. Your app's own `jvmTarget` does not have to match (Java 8 is
fine); `d8` compiles all of these to the same DEX bytecode.

## Build

| Toolchain | Version |
|---|---|
| JDK | 17 |
| Gradle | 9.7.1, via the wrapper (9.6.0 is AGP's minimum) |
| Android Gradle Plugin | 9.4.0 |
| Kotlin | supplied by AGP |
| Wire | 6.4.7 |
| `compileSdk` / `minSdk` | 35 / 24 |
| Android NDK | r26+ |

AGP 9 has built-in Kotlin support, so there is no
`org.jetbrains.kotlin.android` plugin and no `kotlinOptions` block.
`jvmTarget` follows `compileOptions`.

Prerequisites:

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi \
                  i686-linux-android x86_64-linux-android
cargo install cargo-ndk
export ANDROID_NDK_HOME=...   # NDK r26+
```

Then run the wrapper, which downloads Gradle (system Gradle is not used):

```sh
./gradlew :core:assembleRelease
```

which runs, in order:

1. `cargoNdkBuild` cross-compiles `polycentric-core` (cdylib) for the
   four Android ABIs into `core/src/main/jniLibs/` via cargo-ndk.
2. `cargoHostBuild` + `uniffiGenerate` builds a host cdylib and runs
   `tools/uniffi-bindgen` (`uniffi-bindgen generate --library ... --language
   kotlin`) into `core/build/generated/uniffi/`. Packages come from each
   crate's `uniffi.toml`: `org.futo.polycentric.ffi` (rs-core) and
   `org.futo.polycentric.ffi.common` (rs-common, e.g. validation errors).
3. Wire proto generation + normal Kotlin/AAR build.

To rebuild Kotlin components without rebuilding Rust: `./gradlew build -PskipRust=true`.

## Formatting

Commits touching `*.kt` are formatted by the repo's pre-commit hook (set
it up with `pnpm prepare` at the repo root). The hook runs
`ktlint-staged.sh`, which runs `:core:ktlintFormat` on just the staged
files (`-PktlintStagedFiles`) so nothing outside the commit is rewritten.
ktlint runs through Gradle, so committing `kt-core` changes requires the
build toolchain (JDK 17+ and the Android SDK).
