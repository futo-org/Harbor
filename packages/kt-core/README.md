# polycentric-kt-core

Kotlin/Android SDK for Harbor: a thin, idiomatic Kotlin wrapper over the
Harbor client SDK in Rust (`packages/rs-core`), reached through
UniFFI-generated bindings.

## Architecture

1. **The app** (e.g. [Grayjay](https://gitlab.futo.org/videostreaming/grayjay)) opens a
   `PolycentricClient` and calls its functions.
2. **polycentric-core** is this library: suspend functions and flows over rs-core's
   `HarborClient`, plus an Android Keystore `KeyCipher`.
3. **The FFI** is generated by `uniffi-bindgen` from `rs-core` into `org.futo.polycentric.ffi`.
4. **rs-core** does the work: local storage (SQLite), key custody and signing, the commit
   pipeline, sync, identities, pairing, backups, the query engine, and gRPC transport.

Protocol types are the UniFFI records rs-core generates from `protos/polycentric/v2` — data
classes for messages (`Content`, `Post`, `EventBundle`, `EventKey`, ...), sealed classes for
oneofs (`ContentBody.Post`, `QueryData.Feed`, ...) and enums — used as they are. Signed bytes
never cross the FFI: `SignedEvent.event` and `SerializedContent.content` are decoded views, events
are named by `EventKey` and content by `ContentDigest`. Records hold bytes as `ByteArray`, which
`equals` compares by reference; compare keys with the `contentEquals` extensions here.

Errors are the generated `SdkException` subclasses (`NoActiveIdentity`, `AlreadyExists`,
`Network`, ...). A failed `query` flow throws `QueryException`.

### Opening a client

```kotlin
// Android: SQLite in the app's database directory, blobs in filesDir/polycentric-blobs,
// private keys sealed with an Android Keystore key.
val client = PolycentricClient.create(context, seedServers = listOf("https://srv1.example"))

// JVM/desktop: a database needs a KeyCipher; aeadKeyCipher seals with a 32-byte wrapping key
// (from generateWrappingKey()) that the host keeps safe.
val client = PolycentricClient.open("/path/db.sqlite", aeadKeyCipher(wrappingKey))

// Tests and throwaway sessions: nothing is stored, no cipher needed.
val client = PolycentricClient.inMemory()
```

`PolycentricClient.open(config: HarborClientConfig, keyCipher)` takes a full config. Private keys
never leave rs-core except sealed by the `KeyCipher`; opening a database with a different cipher
restores no login. Apps with their own keystore implement `KeyCipher` (`seal`/`open`).

Databases written by earlier kt-core versions (`polycentric-v2.db`) open in place: rs-core migrates
their schema and seals any private keys they stored unsealed on first open.

### Using it

```kotlin
val login = client.createIdentity()                  // publish an identity and sign in
client.publish(ContentBody.Post(Post(text = "hi")).toContent(), Collections.FEED)

val pending = client.prepareEvent(content, Collections.FEED)  // signed, not stored
show(pending.bundle())
client.commitEvent(pending)

client.listValidEvents(login.identity, Collections.FEED).map { it.body }

client.snapshot.collect { render(it) }               // StateFlow<ClientSnapshot>: state, login, servers
client.events.collect { event -> }                   // Flow<ClientEvent>, from when collected
client.committed.collect { bundle -> }               // Flow<EventBundle> stored on this device

client.query(Query.GetProfile(GetProfileArgs(identity)), queryKey = listOf("profile", identity))
    .collect { result -> (result.data as? QueryData.Profile)?.response }
client.awaitQuery(query)                             // first successful QueryData, or null

client.sync()                                        // SyncStrategy.PARTIAL by default
val backup = client.createBackup(); client.checkBackup(backup)
```

`PolycentricClient` covers the whole `HarborClient` surface (blobs, logins, pairing, identity
updates, moderation, push registration, legacy import); `client.ffi` is the underlying object.
rs-core's free functions — `eventKeyId`/`parseEventKeyId`, `encodePairingCode`/
`decodePairingCode`, `blobUrls`, `imageProxyUrls`, `digestKey`, `collectBlobs`,
`validateContent`, `backupInfo`, `normalizeAlias`, `resolveAlias`, `processImageToJpeg`,
`aeadKeyCipher`, `generateWrappingKey` — are called directly from `org.futo.polycentric.ffi`.
`close()` the client when done.

## Using this library

Published to the project's Forgejo Maven registry at `code.futo.org` on release tags as
`org.futo:polycentric-core`. Add the registry to your repositories:

```kotlin
maven {
    url = uri("https://code.futo.org/api/packages/harbor/maven")
}
```

What your app needs:

- `compileSdk` >= 35
- `minSdk` >= 24
- Kotlin >= 2.2
- JDK (for building, not runtime) >= 17

The AAR declares no minimum Gradle or AGP version, so those stay your choice.

Library classes are Java 17 bytecode. Your app's own `jvmTarget` does not have to match (Java 8 is
fine); `d8` compiles all of these to the same DEX bytecode.

## Build

| Toolchain | Version |
|---|---|
| JDK | 17 |
| Gradle | 9.7.1, via the wrapper (9.6.0 is AGP's minimum) |
| Android Gradle Plugin | 9.4.0 |
| Kotlin | supplied by AGP |
| `compileSdk` / `minSdk` | 35 / 24 |
| Android NDK | r26+ |

AGP 9 has built-in Kotlin support, so there is no
`org.jetbrains.kotlin.android` plugin and no `kotlinOptions` block.
`jvmTarget` follows `compileOptions`.

Prerequisites:

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi \
                  i686-linux-android x86_64-linux-android
cargo install cargo-ndk
export ANDROID_NDK_HOME=...   # NDK r26+
```

Then run the wrapper, which downloads Gradle (system Gradle is not used):

```sh
./gradlew :core:assembleRelease
```

which runs, in order:

1. `cargoNdkBuild` cross-compiles `polycentric-core` (cdylib, with SQLite
   bundled) for the four Android ABIs into `core/src/main/jniLibs/` via
   cargo-ndk.
2. `cargoHostBuild` + `uniffiGenerate` builds a host cdylib and runs
   `tools/uniffi-bindgen` (`uniffi-bindgen generate --library ... --language
   kotlin`) into `core/build/generated/uniffi/`. Packages come from each
   crate's `uniffi.toml`: `org.futo.polycentric.ffi` (rs-core) and
   `org.futo.polycentric.ffi.common` (rs-common, e.g. validation errors).
3. The normal Kotlin/AAR build.

To rebuild Kotlin components without rebuilding Rust: `./gradlew build -PskipRust=true`.

Unit tests (`./gradlew :core:testDebugUnitTest`) run the wrapper against the real rs-core,
built for the host and loaded through JNA from `target/release`.

## Formatting

Commits touching `*.kt` are formatted by the repo's pre-commit hook (set
it up with `pnpm prepare` at the repo root). The hook runs
`ktlint-staged.sh`, which runs `:core:ktlintFormat` on just the staged
files (`-PktlintStagedFiles`) so nothing outside the commit is rewritten.
ktlint runs through Gradle, so committing `kt-core` changes requires the
build toolchain (JDK 17+ and the Android SDK).
