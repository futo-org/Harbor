# polycentric-kotlin-sdk

Kotlin/Android SDK for Harbor, published as `org.futo:polycentric-kotlin-sdk`. It mirrors
`packages/js/js-sdk`: a wrapper around the shared Rust protocol engine `packages/rust/rs-core`, using
UniFFI-generated Kotlin bindings.

## Architecture (in layers)

1. **The app** (e.g. [Grayjay](https://gitlab.futo.org/videostreaming/grayjay)) constructs a
   `PolycentricClient` with a storage driver and a file-store driver, then calls it.
2. **polycentric-core** (this library) owns key custody, persistent storage, and control flow
   such as initialization and sync.
3. **The FFI** (`org.futo.polycentric.ffi`), generated by `uniffi-bindgen` from `rs-core`.
4. **rs-core**, shared with `js-sdk`, owns sequences, Merkle anchors, vector clocks,
   validation, the query engine, gRPC transport with TLS, and image processing.

Protobuf messages (`polycentric.v2`) are generated by [Wire](https://github.com/square/wire)
from `protos/polycentric/v2/*.proto`.

## Module map

Sources are in `core/src/main/kotlin/`.

| `js-sdk` | `kotlin-sdk` |
|---|---|
| `polycentric-client.ts` | `PolycentricClient.kt` |
| `client-internal/identity-manager.ts` | `IdentityManager.kt` |
| `client-internal/content-manager.ts` | `ContentManager.kt` |
| `client-internal/keypair-manager.ts` | `KeyPairManager.kt` |
| `client-internal/pairing-session-manager.ts` | `PairingSessionManager.kt` |
| `client-internal/event-service.ts` | `EventService.kt` |
| `crypto/crypto-manager.ts` | `Ed25519CryptoManager.kt` |
| `crypto/server-jwt.ts` | `ServerJwt.kt` |
| `errors.ts`, `constants.ts` | `Errors.kt`, `Constants.kt` |
| `platform-interfaces/*` | `PlatformInterfaces.kt` |
| `memory-storage/memory-storage.ts` | `Fakes.kt` (test sources) |
| `js-datastore-sqlite`: `DrizzleStorageDriver` | `SqliteStorageDriver.kt`, `SqliteSchema.kt`, `PolycentricDbHelper.kt`, `Sql{Event,Content,Keys}Repository.kt` |
| `node-sdk`: `NodeFileStoreDriver` | `AndroidFileStoreDriver.kt` |

Kotlin-only: `Queries.kt` (typed `PolycentricClient` extensions over the core's query
engine: profiles, feeds, threads, verification claims), `FfiExt.kt` (folds the bindings'
`CoreException` into `CoreFailureException`) and `ProtoExt.kt` (Wire ↔ FFI key conversions).

Not ported: `client-internal/login-manager.ts`, `data-store/*` (`StorageHandle` and its
stores), `file-store/file-store.ts`, `utils/moderation.ts`, and the byte/hex/base64/path utils.

## Using this library

Release tags publish to the project's Forgejo Maven registry. Add it to your repositories:

```kotlin
maven {
    url = uri("https://code.futo.org/api/packages/harbor/maven")
}
```

Your app needs `compileSdk` >= 35, `minSdk` >= 24, Kotlin >= 2.2, and JDK >= 17 to build.
The AAR declares no minimum Gradle or AGP version. Library classes are Java 17 bytecode,
but your app's `jvmTarget` need not match (Java 8 is fine): `d8` compiles both to DEX.

## Build

The toolchain is pinned in `gradle/libs.versions.toml` and the Gradle wrapper (system
Gradle is not used): JDK 17, AGP 9.x with its built-in Kotlin (no
`org.jetbrains.kotlin.android` plugin or `kotlinOptions`; `jvmTarget` follows
`compileOptions`), Wire, and Android NDK r26+.

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi \
                  i686-linux-android x86_64-linux-android
cargo install cargo-ndk
export ANDROID_NDK_HOME=...   # NDK r26+
./gradlew :core:assembleRelease
```

`preBuild` runs, in order:

1. `cargoNdkBuild`: cross-compiles `polycentric-core` (cdylib) for the four Android ABIs into
   `core/src/main/jniLibs/` via cargo-ndk.
2. `cargoHostBuild` + `uniffiGenerate`: builds a host cdylib and runs `tools/uniffi-bindgen`
   into `core/build/generated/uniffi/`. Packages come from each crate's `uniffi.toml`:
   `org.futo.polycentric.ffi` (rs-core) and `org.futo.polycentric.ffi.common` (rs-common).
3. Wire proto generation, then the normal Kotlin/AAR build.

To rebuild only the Kotlin side, pass `-PskipRust=true`. This reuses the existing
`jniLibs` (`checkNativeLibs` fails the build if any ABI is missing) and generated bindings.

## Formatting

The repo's pre-commit hook (set up by `pnpm prepare` at the repo root) runs
`ktlint-staged.sh`, which runs `:core:ktlintFormat` on just the staged `*.kt` files
(`-PktlintStagedFiles`). ktlint runs through Gradle, so committing `kotlin-sdk` changes needs
JDK 17+ and the Android SDK.
